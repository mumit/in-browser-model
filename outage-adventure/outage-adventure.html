How it works
  • The engine owns the truth. Rooms, items, locks and the puzzle live in plain JavaScript. The model can't add an item, open a door or win the game for you.
  • Understanding: a fast rules parser handles common commands. Anything else goes to a small embedding model (MiniLM), which compares what you typed with every action that is valid right now and picks the closest, if it scores above 0.48. It can only ever choose a real action.
  • Why not a chat model? We tested Qwen2.5 0.5B in Chrome: it rarely produced valid JSON and picked from a lettered list little better than chance. Meaning-matching with a 23 MB model was far more reliable.
  • Narration: the narrator model is given the engine's own line and asked to rewrite it in a voice, with one example. Plain mode skips the model entirely. Small models still embellish, which is why the engine's line is always shown underneath.
  • Grounding check: after each narration, we scan for any item, place or direction from the game world that the narrator mentioned but isn't actually there, and flag it. It only knows the game's own vocabulary, so an invented suitcase slips through: checking against a closed list has limits too.
  • Hints cost 5 moves. Fewest moves wins.
  • Everything runs in this tab. Nothing leaves your machine.
